# 07 — Enforce a runtime IPC channel allowlist in the preload

**What to build:** `apps/desktop/src/preload/index.ts` exposes a generic `invoke` whose channel argument is only constrained at compile time by `IpcChannelMap`. At runtime any string is passed straight to `ipcRenderer.invoke`, so a compromised renderer's reachable surface is every registered channel rather than a declared subset. Add a runtime allowlist in the preload so `invoke` and `on` reject channels outside the declared contract.

**Blocked by:** None, but the preload is a shared area — the change must be called out with impact and tests and needs maintainer approval before merge.

**Status:** resolved

## Proposed direction

- Derive or maintain a literal allowlist of channel names in the preload (kept adjacent to the `@ipc/channels` declarations so drift is caught by a test).
- `typedInvoke`/`typedOn` throw on any channel not in the list before touching `ipcRenderer`.
- Extend `tests/auth/electron-security.spec.ts` with a case proving an unlisted channel is rejected in the renderer without reaching the main process.

## Triage verification

- **Claim confirmed.** The preload's `typedInvoke` and `typedOn` cast the channel to `string` and pass it straight to `ipcRenderer.invoke`/`ipcRenderer.on`; the only constraint is the compile-time `keyof IpcChannelMap` / `keyof IpcEventMap` type, which does not exist at runtime. A compromised renderer can call `window.api.invoke('<any-channel>')` and reach any registered handler.
- **Severity confirmed as medium-low (defence-in-depth).** All three `authentication:*` session handlers call `requireTrustedRendererSender` in the main process, re-verifying the sender frame against the trusted renderer entry URL before touching session material, so the allowlist adds a second layer rather than closing an open hole. The `language:*` handlers carry no sensitive material.
- **Redundancy check.** No runtime channel allowlist exists anywhere under the desktop source (searched preload, main, and shared IPC modules); the only runtime allowlisting in the codebase is the unrelated Supabase private-hostname check. Not already implemented.
- **Prior rejection check.** No `.out-of-scope/` knowledge base exists in this repo; nothing resembling this request was previously rejected.
- Declared contract at verification time: 6 invoke channels (`authentication:read-session`, `authentication:replace-session`, `authentication:clear-session`, `language:get-bootstrap`, `language:get-language-mode`, `language:set-language-mode`) and 1 event channel (`language:language-mode-changed`) — the allowlist must be derived, not hand-copied, so this list can grow without drift.

## Agent Brief

**Category:** enhancement
**Summary:** Enforce a runtime IPC channel allowlist in the preload so `invoke` and `on` reject channels outside the declared contract

**Current behavior:**
The preload bridge exposes `invoke` and `on` functions whose channel parameter is constrained only at compile time by `IpcChannelMap`/`IpcEventMap` (module-augmented interfaces on `@ipc/channels`). At runtime the channel string is forwarded unchecked to `ipcRenderer`, so script running in a compromised renderer can invoke any registered main-process channel, not just the declared subset. Existing session channels mitigate this by re-verifying the sender in the main process (`requireTrustedRendererSender`), which must remain in place.

**Desired behavior:**
The preload holds a runtime allowlist of channel names — one set for invoke channels, one for event channels — kept adjacent to the `@ipc/channels` declarations so a test catches drift between the compile-time interfaces and the runtime lists. `invoke` throws synchronously (rejecting before `ipcRenderer.invoke` is ever called) for any channel not in the invoke allowlist; `on` throws for any channel not in the event allowlist. Allowed channels behave exactly as before.

**Key interfaces:**
- The `window.api` bridge shape (`invoke`, `on`) must not change for allowed channels — same signatures, same return types
- The allowlist values must stay in lockstep with the keys of `IpcChannelMap` and `IpcEventMap`; a drift test must fail when a channel is declared in the interface but missing from the runtime list (adding a new channel should require updating both, with the test as the guard)
- Rejection should be a thrown `Error` naming the offending channel, without echoing any payload

**Acceptance criteria:**
- [x] Calling `invoke` with an unlisted channel throws in the renderer and no IPC message reaches the main process
- [x] Calling `on` with an unlisted channel throws and registers no listener
- [x] All currently declared channels (6 invoke, 1 event at triage time) continue to work end-to-end; existing auth and i18n test suites stay green
- [x] A drift test fails if a channel key exists in `IpcChannelMap`/`IpcEventMap` but not in the runtime allowlist (and vice versa)
- [x] The Electron security spec gains a case proving an unlisted channel is rejected from the renderer without reaching the main process

**Out of scope:**
- Removing or weakening the main-process sender re-verification (`requireTrustedRendererSender`) — the allowlist is additive defence-in-depth
- Changing the shape of `IpcChannelMap`/`IpcEventMap` or the module-augmentation pattern for declaring channels
- Rate limiting, payload validation, or any other IPC hardening beyond channel-name allowlisting

**Shared-area callout:** the preload is a shared area per the repository rules — the implementation PR must state impact and tests explicitly and obtain maintainer approval before merge.

## Implementation record

Implemented and approved by the maintainer (deliberate self-review of the shared-area changes).

- Runtime allowlist lives in `apps/desktop/src/shared/ipc/channel-allowlist.ts` (adjacent to the `@ipc/channels` declarations, since the `preload/generic-bridge` verifier rule forbids Channel literals inside `src/preload/`); `satisfies Record<keyof IpcChannelMap/IpcEventMap, true>` locks it to the declared keys at compile time in both directions
- `typedInvoke`/`typedOn` in `apps/desktop/src/preload/index.ts` throw synchronously for unlisted channels before touching `ipcRenderer`; the error names the channel and echoes no payload; the `window.api` bridge shape is unchanged
- Drift test `apps/desktop/tests/unit/ipc-channel-allowlist-drift.test.mts` parses declared Channel keys from `src/shared/ipc/*/types.ts` and asserts exact set equality with the runtime lists; verified red under a deliberate allowlist mutation
- `tests/auth/electron-security.spec.ts` gained the rejection case: unlisted `invoke` throws and a main-process probe handler records zero calls; unlisted `on` throws; `language:get-language-mode` still works through the same bridge (passed against the real built app)
- Shared-area impact: `src/preload/` enforcement change plus a one-spec extension of `PRELOAD_ALLOWED_IMPORTS` in `scripts/architecture/verifier.mjs` (`'../shared/ipc/channel-allowlist'`); the preload Channel-literal ban itself is unchanged; canonical verifier fixture updated
- Verification: `verify:architecture` (30/30 + real tree), `test:unit` 5/5, typecheck, lint all green; 4 `tests/i18n` failures and the CSP spec failure were confirmed pre-existing local-environment issues via a stashed-baseline rerun (they also fail without this change; the full suite is green under `scripts/run-auth-e2e.sh` with the disposable Supabase harness)
- `requireTrustedRendererSender` main-process re-verification untouched (out of scope)
