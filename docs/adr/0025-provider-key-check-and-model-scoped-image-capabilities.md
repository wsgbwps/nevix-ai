# ADR-0025: Provider Key 检查与图片模型独立能力

## 状态

已接受 — 2026-09-29。

## 决策

AI Provider Connection Check 只用固定 Kapon `/v1/models` 路由验证 Key 是否有效，不用返回的模型列表决定媒体或模型可用性。有效 Key 对图片与视频媒体产生相同的检查结论；连接仍须启用且满足其他准入条件。具体模型、比例、分辨率及参考图上限由随 Nevix 发布的 AI Provider Capability Manifest 确定，真实生成失败仍按 Generation Task 的失败语义处理。这样新增模型无需重查已配置连接，且模型清单只有一个开发者维护的权威来源。此决定取代 ADR-0016 中「固定模型可见性决定媒体可用性」的规则。

图片比例改为模型级能力：豆包模型保留现有 8 种比例，`gemini-3.1-flash-image` 发布 Apifox 合同中的 14 种；媒体级比例保留原有 8 种作为旧合同字段。新版 Desktop 按所选模型提供比例并校验草稿，Server 按所选模型执行准入。切换模型时，若当前比例不被新模型接受，采纳新模型默认比例；Manifest 更新不会静默改写既存草稿。既有有效连接在升级迁移时将图片与视频状态归一为可用，不重查 Key，也不存储模型可见性。

Gemini 文生图与参考图生图分别使用 Kapon 的 OpenAI 风格同步端点，固定请求 `response_format=url`；单次供应商请求生成一张，Nevix 的 1–4 张数量沿用逐张调用。Gemini 的默认分辨率为 `1K`，首次图片模型仍为豆包 Pro。真实 URL 生成由发布时人工 smoke 验证，不作为运行时能力激活门槛。
