# ADR-0023: 冻结历史引用缺失时保留成品与任务的可读性

## 状态

已接受 — 2026-09-24。实施方案已获整体验收；本 ADR 不表示源码已实现。

## 背景

Generation Specification 冻结了提交时的引用顺序，[ADR-0016](0016-ai-creation-v1-trusted-seams.md) 要求发布保存完整素材快照，但旧任务可能无法再确认某项 Reference Material 记录或任务保留关系。当前 Admin Inspiration 详情因此把仍存在的 Media Asset 报为 404；Asset Library 则跳过缺失项，可能误称“未使用参考素材”。TaskCard 虽保留冻结卡位，但把历史缺失与可重试的缩略图加载故障混为一谈。

2026-09-24 对本地开发库的只读全量审计发现：39 个任务有 16 个冻结引用位，其中 12 位缺少素材记录，涉及 9 个任务、2 件未删除 Media Asset（`5b8903e0-1fc7-4596-823d-21ffaae1c3a5`、`df927174-2f5c-4508-b860-a953f271040f`）；“素材仍在但任务保留关系缺失”为 0。这只说明该开发库的当前状态，不证明素材消失原因或其他部署的情况。

## 决策

- **历史意图和素材可用性分开。** 已授权且未删除的 Media Asset 详情继续返回成品与完整冻结 Generation Specification。Admin Inspiration 与 Creator Asset Library 的可读素材列表只含同时具备素材记录和该任务保留关系的引用，按冻结顺序构成有序子序列。Desktop 按冻结位置展示可用项或“历史参考素材不可用”占位，保留编号、角色和总数；仅冻结引用本来为空时才写“未使用参考素材”。缺失项不补造文件名、元数据或媒体字节。
- **TaskCard 读取明确的任务历史状态。** 任务列表的每个任务摘要在不可变 `snapshot` 之外携带按冻结引用位置一一对应的 `reference_availability` 布尔数组；Go 在同一只读 `REPEATABLE READ` 快照中读取一页任务，再以一次批量查询确认素材记录及该任务保留关系。TaskCard 对 `false` 显示同一占位，不请求其缩略图。该数组表示历史引用完整性，不证明对象存储字节可读；对象存储或网络失败仍显示可重试的加载失败。任务详情、冻结规格和任务 `updated_at` 不因这项读取投影改变；状态随对应列表页重新读取更新，无需为人工恢复建立实时推送。
- **预览逐项授权。** Admin 详情中一项缺失不妨碍其他已确认引用的预览；缺失项的预览仍拒绝。User 对自己仍有效 Reference Material 的独立读取权不因任务保留关系异常而撤销，但这项权限不能证明该任务的历史引用完整。
- **发布保持完整快照。** 首次发布仍须在 Go 写事务中确认全部冻结引用，不能静默省略。Asset Library 的发布确认按冻结引用计数；已知有缺失项时说明原因并禁用提交。列表级 `can_publish` 仍只表达所有权及治理准入，详情再以历史引用完整性禁用提交。授权通过但提交时发现引用不完整，返回 `409 asset_reference_unavailable`，不创建 Publication 或部分快照；资产不存在、已删除或无权访问仍使用现有资源错误。已有 Team Publication 继续依据自身独立快照读取和 Create Similar。
- **只读审计与恢复分开。** 本轮只对本地开发库报告素材记录缺失和保留关系缺失的数量及受影响资产 ID。不自动重建历史记录或对象；恢复须另行验证原始数据和不可变对象证据。

## 取舍

- 维持整件资产 404 会把局部历史损坏伪装成资产不存在；用冻结规格与有序子序列已足够表示缺口，无需为两处资产详情新增逐项状态字段。同一素材 ID 可以在冻结规格中重复出现，Desktop 不得按 ID 建唯一映射或按返回数组重编位置。
- TaskCard 不能从缩略图 404 推断永久缺失：本人活跃素材可能凭独立权限取得缩略图，而网络或对象存储也可能使缩略图失败。只在任务详情增加状态会被 `updated_at` 增量缓存留住旧值；逐卡新端点增加请求，因此状态放在每次重读的任务列表摘要上。
- 本 ADR 对 [ADR-0016](0016-ai-creation-v1-trusted-seams.md) 的列表单查询保证作窄修订：任务行摘要及其 `updated_at` 判据仍由原来的单条查询取得；`reference_availability` 是同一列表响应中另行批量读取的辅助投影，不属于 Generation Task 详情，也不受 `updated_at` 判据覆盖。两次查询共用一个数据库快照；Desktop 即使看到相同 `updated_at`，也采用新列表响应里的可用性数组。
- 列表较早的已加载历史页在人工修复后可能暂时保留旧状态，重新进入或重新读取该页后收敛。所有媒体读取仍由 Go 当次授权，不信任列表状态作权限凭证。
