# ADR-0005: Creation 业务动作与任务刷新采用不同生命周期

## 状态

已接受 — 2026-09-05。用户已确认责任、产品规则与测试合同，自包含实施规格见 [#189](https://github.com/wsgbwps/nevix-ai/issues/189)；本 ADR 不表示源码已经实现。

## 背景

Creation Workbench 的页面存活、Creation Session 选择、Draft 编辑、素材上传和生成提交目前由同一页面状态驱动。普通导航会卸载页面，但请求可能已经到达 Go；仅判断 mounted 或当前 Creation Session identity，不能同时表达业务动作能否继续与响应能否更新当前展示。把任务刷新混在这些动作中，也使重连补读、读取顺序和展示一致性缺少单一 owner。

## 决策

在 AI Creation Domain 内区分两个 module，保持 [根 ADR-0012](../../../../docs/adr/0012-unified-ai-creation-owner.md) 的统一 creation owner；app 只装配，implementation 不进入 composition root。

- **Creation Workbench module** 拥有 Draft、Reference Material、展示生命周期，以及上传、提交、取消、重试等业务动作。进行中的动作持有自己的目标、固定输入与 File；它们可在当前登录期间跨普通页面导航继续，完成后不能接管后来选择的创作上下文。
- **Generation Task 刷新 module** 拥有任务列表与详情的读取、刷新调度、旧结果失效和一致展示状态。它只持续更新当前展示的 Creation Session，离开后停止展示读取，重新进入主动补读。它不修改 Draft，也不发起业务命令；业务动作完成后触发核对，由该 module 获取服务端事实。

展示与业务动作的资格分别判定。A → B → A 的第二次进入不能接受第一次进入的旧读取、失败提示或完成通知。退出登录、确认 Session 失效、切换 Server URL 后，旧业务动作不得继续发起请求或借用新的 Session；本地失效不代表已发送的写入被撤销。关闭或重载应用不承诺客户端操作续跑。

点击提交即固定本次提示词、参数、参考素材及顺序，以及 Reference Mention 展开采用的 Interface Language；后续编辑不改变本次意图。上传后的素材身份替换只能完成原意图的绑定，Go 仍负责权威校验和形成 Generation Specification。已开始提交但尚未获得 Creation Session identity 的 Draft 保留独立归属和临时恢复条目，不能与后来新 Draft 共用可被迟到响应覆盖的归属。

一次生成提交的恢复复用其固定载荷与幂等键。创建会话或上传的结果未确认不等同于明确失败；没有幂等合同的动作不自动盲目重发，也不能按提示词相似性认领服务端结果。

同一创作上下文最多一条尚未完成的准备／提交链，结果未确认期间仍占用该位置；其他上下文可以独立提交。Go 确认受理后即可发起下一次提交，不等待 Generation Task 终结。

修改 Draft 或移除引用不破坏进行中动作持有的 File 与素材引用；实际素材删除延后，删除所属 Creation Session 等待准备／提交链收尾。用户可明确停止本地追踪并重新开始，保留 Draft，但此前已发送的写入不因此撤销，迟到响应也不得再启动后续步骤。

### 刷新调度与一致展示

SSE 正常时以事件驱动刷新并合并连续通知；断流且当前会话有进行中任务时，每 5 秒兜底轮询。进入会话、重连成功和业务动作完成后立即核对，离开创作台后停止持续读取。同一展示生命周期内任一时刻最多一轮在途读取，期间的新触发合并为后续核对；失效轮次的迟到结果不得更新展示。

约 10 秒是发现断流或重连成功后的恢复目标，受正常请求完成条件约束；本次不保证 SSE 看似在线却静默失效时的发现时限，不为拼出固定时限而任意采用 5 秒读取超时。

以单个 Generation Task 保持展示一致性，不把不同读取轮次的任务状态、结果位与 Generation Specification 混在一起。详情失败保留该任务最后一致结果并标明未更新，新增任务详情未到则表达加载或失败；其他任务不受该项失败阻塞。

增量补读依赖 [根 ADR-0016](../../../../docs/adr/0016-ai-creation-v1-trusted-seams.md) 的 Go 详情读取合同：先保证一致读取，再证明能否复用 `updatedAt`，无法可靠满足时才增加 `revision`。客户端用可靠判据区分新增、变化、此前失败与可复用的详情；缓存判据对应实际读到的那份详情，不以另一轮列表摘要替代。该合同补齐是任务增量刷新的独立前置，不阻塞 Workbench 业务动作生命周期工作。

### 历史任务与展示资源

任务历史采用向上分页：首次加载最新 20 条并定位到底部，接近顶部再加载 20 条，插入历史保持阅读位置；不设 50 条展示上限。20 条是初始批量，后续以目标设备实测调整。状态刷新保留已加载历史，仅补读必要详情。

在底部时跟随新任务，阅读历史时保持位置并提供轻量的新任务提示；明确返回底部后才恢复跟随。历史插入、媒体真实尺寸和 Composer 几何变化都必须纳入阅读锚点的维护。

使用虚拟列表与媒体按需加载，媒体缓存有容量限制。切换会话释放展示资源；进行中业务动作持有的 File 不因展示释放而丢失。分页与任务数据知识留在 Creation 内，展示位置和虚拟测量不进入可信 Go seam。

以可访问的 Mac / Windows 环境记录实际配置，通过长历史与混合媒体实测确定批量、预渲染范围和缓存字节预算；验收记录同时证明阅读位置稳定、挂载数量受控、缓存预算和资源释放，不把未经实测的设备表现当作保证。

## 取舍与约束

只在所有操作完成后允许导航更简单，但会让网络延迟阻塞创作与设置；因此接受将进行中业务动作与展示订阅分开的成本。把两个 module 合成页面级大 module 则会重新耦合操作存活与刷新时序，削弱 locality。

不为跨普通导航继续引入持久任务队列或新的可信服务端通路。[根 ADR-0014](../../../../docs/adr/0014-go-sole-trusted-data-plane.md) 的 Go 唯一可信数据面与 SSE 补读原则继续适用；[根 ADR-0018](../../../../docs/adr/0018-result-reuse-reupload-in-renderer.md) 的结果重上传决定保持不变。

Draft 的设备本地语义与临时归属由 [根 ADR-0017](../../../../docs/adr/0017-device-local-session-draft.md) 定义。安全恢复同一次提交只限当前登录期间；重启或重新登录后只能核对 Go 中已有事实，不能保证认领旧操作，再次提交是新动作。

## 验证与实施边界

两个 module 以既有 Creation ports 和生产等价的测试 adapter 验证可观察行为，通过可控响应顺序、失败与时钟覆盖生命周期和刷新交错。保留少量真实页面测试覆盖导航、滚动、Composer 和媒体几何变化；复用 URL owner 与 Blob cache 测试覆盖资源使用和回收，Go 详情合同由服务端集成测试验证。

共同定稿不要求共同实施。Workbench 业务动作生命周期与 Go 详情合同前置可独立推进；任务增量刷新依赖后者。历史分页、虚拟列表和媒体预算按完整可验证的行为拆片，不因共享页面设立虚假阻塞关系。具体验收与后续实施票由 [spec #189](https://github.com/wsgbwps/nevix-ai/issues/189) 承载。
